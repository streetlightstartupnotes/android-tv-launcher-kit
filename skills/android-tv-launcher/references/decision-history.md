# 可复用的方案取舍

本页是去关联后的工程结论，不包含实际设备、人员、品牌或会话记录。

| 曾尝试或考虑的方向 | 暴露的问题 | 可复用判断 |
|---|---|---|
| 观察原生窗口，出现桌面就拉自有Activity | 会把正常电视/设置/HDMI画面顶掉 | 只接受明确前台转交，不做后台抢回 |
| 全局无障碍过滤HOME，再加系统广播兜底 | 多入口竞争、方向多跳兼容问题难排除 | 拆开系统HOME路由和应用内按键；移除自己的旧过滤链并实机复测 |
| MENU遇FLAG_CANCELED一律拒绝 | 特定固件实体MENU也被虚拟转发成取消事件 | 完整观测后只对精确签名兼容，默认关闭例外 |
| MENU无条件在UP打开 | 失焦、取消、重复松手会产生多余动作 | 按key/downTime配对，生命周期清理 |
| MAIN包自己带INFO启动门 | 正常点应用图标可能被门吞掉，已有任务可能被意外带前台 | 厂商入口独立包/任务，普通图标保持普通启动 |
| 开机入口onResume立即启动，或只等很短时间 | 尚无焦点、被挡住或冷启动负载下失败 | 等真实焦点，有限期限，暂停即取消 |
| 无焦点后定时重试直到主界面出现 | 抢占后来开始使用的原生内容 | 失败停止并记录，不能以成功率掩盖冲突 |
| 同一标记同时表示请求已消费和开场已完成 | 打断后可能省略开场，或者重入后重复播放 | 分清请求、转交、呈现状态，明确保守消费取舍 |
| 用set-home命令Success当成默认HOME完成 | 某些固件内部拒绝第三方HOME | 回读实际resolver并按键测试 |
| 禁用原生桌面整个包 | 原生看电视/设置等能力可能一并受损 | 共存场景不采用；权限缺口如实交付 |
| 不断堆粒子满足“更密” | 电视GPU与带宽不足，离线预览误导 | 按当前视觉目标选实现，逐阶段实机测量 |
| 用应用内六秒开场代表系统启动动画 | 实际上电与系统阶段仍显示厂商品牌 | 启动分层验收，应用动画只算应用阶段 |
| 只测重启，不测电源短按 | 厂商睡前强制HOME并杀第三方，唤醒落点不同 | 冷启动与遥控待机单独记录和测试 |
| 恢复配置时无条件覆盖当前值 | 覆盖用户后续调整或其他服务 | 校验设备，比较after，保留后改值 |
| 回滚UI时顺便重新启用旧Guard | 已去掉的过滤冲突又被带回 | 恢复画面、默认路由、无障碍、启动项各自独立 |
| 同版本反复写APK | 历史校验与回退包不再可信 | 版本产物不可覆盖，保存校验与签名 |
| 直接压缩整个项目目录 | 签名、截图、日志、设备配置和品牌文件混入 | 新建白名单分享树，扫描并验证最终zip |

## 开源项目与固件研究路线

开源桌面、去广告或精简脚本可作为研究材料，先看源代码、作用范围、回滚和目标固件差异。名称相似的教程或同品牌其他型号成功，不是这台设备的权限与兼容证据。不要把整包清理脚本默认为桌面安装的一部分；提取实际需要、已核对的动作。

系统bootanimation和上电Logo通常属于应用层之外。只读调查应确认实际路径、权限、格式和调用优先级；发现候选字符串不等于该路径被使用。无法安全支持时保留限制，不伪造已刷机结果，也不把厂商二进制放入可复用分享包。
