# 验收与证据模板

每个结论分开写：代码实现、本地验证、目标设备观察、用户体验确认。没有测试的格子留“未验证”，不要用同一张截图填满矩阵。

| 场景 | 触发 | 必须记录 |
|---|---|---|
| 完整重启 | 明确系统重启/断电 | boot_count变化、厂商入口、首次焦点、一次转交、最终页面 |
| 遥控待机 | 自有桌面下电源关，等待，再开 | boot_count、睡前后PID/stopped、系统是否强制HOME、醒后页面 |
| 原生待机 | 原生App/HDMI下同样关开 | 是否恢复用户预期页面，自有桌面是否抢走 |
| 普通HOME | 实体HOME、连续HOME | 实际目的地、无重复开场、无延迟二次启动 |
| MENU与BACK | 短按、长按、失焦/组合 | 原生菜单是否打开、返回来源、取消后的松手是否误触 |
| 四方向 | 自有和原生页面各试实体短按 | 每次相邻一个项目；长按另测，不混为多跳 |
| 应用分页 | 多种真实列表长度、末页、边缘 | 页数、焦点锚点、单格宽度、刷新后索引校正 |
| 开场/切换 | 冷实例、前后台打断、快速切面板 | 动画是否正常取消/继续、帧呈现与长帧比例 |
| 屏保 | idle开启/关闭、手动预览、来源退出 | 只在自己前台计时，原生页面不被拉回 |
| 失败与恢复 | 缺少入口、安装失败、配置被他人修改 | 可见失败落点、不循环、后续改值被保留 |

测试窗口里明确是否有人使用电视；有干扰的样本标无效或受限，保留后重新测。不能用自动输入验收所有实体遥控；用户回复也要与自动轨迹分开记录，不替其编造独立事件。

## 最小记录结构

放在包外私人状态目录：

```json
{
  "scenario": "standby-from-custom-home",
  "build": "local-build-label",
  "trigger": "physical-remote-power",
  "expected": "restore-custom-home",
  "observed": "pending",
  "evidence": [],
  "user_confirmation": null,
  "limitations": []
}
```

设备连接地址、身份摘要、包清单和焦点记录可能关联具体设备，属于本地证据，不因采用JSON就适合公开。对外分享只整理不可关联的机制与结论。

## 交付说明

先给当前可用结果，再列对应证据与限制。冷启动只通过一次就写一次，待机没测就写没测；系统bootanimation没改就不能称完整开机定制。历史问题的根因未知时保留未知，后来观察到一个确切原因也不反推所有旧异常均同因。

测试通过之后，新增测试应围绕新改动或未解决疑点；避免反复重启正在使用的电视只为扩大表面覆盖。长期稳定、不同固件、不同遥控器与不同HDMI源仍是各自的验收范围。
